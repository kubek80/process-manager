# Process Manager

A portal for company processes (request a GCP project, onboard to Akamai…) and standards (rules issued by cyber security, platform owners, practices). It generates skills and pull request review agents from both. React + Vite frontend, Go backend, Postgres. Start with `README.md`; server details are in `docs/backend.md`.

## Always

- **Finish every task that changes code by running the `update-docs` skill**, before the final summary and before committing. The in-app Guide (`src/components/GuidePage.tsx`) is the main documentation and must match the code.
- Run the tests that cover what you changed, and `npm run test:all` before saying a change is done. Add tests with every feature and every bug fix.
- Sample content is edited with the skills `edit-process`, `edit-standard` and `manage-catalog`.

## Commands

| | |
| --- | --- |
| `npm run dev` | Postgres (docker compose), Go server, Vite. Set `PM_PG=postgres://pm:pm@localhost:5432` to use an existing Postgres instead of Docker. |
| `npm run test:all` | typecheck, validate, Vitest, Go tests, Playwright |
| `npm test` · `npm run test:server` · `npm run test:e2e` | one level at a time |
| `npm run validate` | sample files in `processes/`, `standards/`, `catalog/` |
| `npm run prompt` | regenerate `docs/llm-prompt.md` and `docs/llm-prompt-standards.md` |
| `npm run db:import` · `npm run export -- <folder>` | files into the database · database out to files |

## Conventions

- **The database is the source of truth** for processes, standards, the lists, roles, feedback and skills. The files in `processes/`, `standards/` and `catalog/` are sample content that fills an empty database; changing them does not change a running installation unless they are imported.
- The formats are `schema/*.schema.json`. The frontend checker (`src/lib/validate.ts`) and the server (`server/internal/schema`) both read them; change a format in the schema, then in the types (`src/types.ts`), the checker, the prompts and the generators (`server/internal/skills`).
- Rights are enforced in the server (`server/internal/httpapi`, `server/internal/rbac`); the frontend only hides controls.
- Skills and review agents are generated by templates in Go, never by an LLM, so they are repeatable.
- Text shown to users is written for business analysts: plain words, no implementation terms.
- Go: `gofmt` and `go vet` clean. Database tests use a real Postgres through `dbtest.NewPool`.
